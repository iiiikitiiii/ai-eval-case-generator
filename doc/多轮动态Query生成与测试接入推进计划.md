# 多轮动态 Query 生成与测试接入推进计划

状态：最小实现草案，阶段 21–23 均待开发。本文描述计划，不代表接口已经实现。

## 目标与取舍

只补充一项能力：根据现有画像、种子用例和被测系统真实回答，动态生成下一轮用户 query，供跑批脚本及金服 Web／App 测试调用。

阶段 6 的预生成多轮脚本继续保留。首版不改原有 Agent F 生成、审核及导出流程，也不建设新的测试平台。对话历史由服务端持久化；外部调用端每轮只提交用例 ID 和被测系统的最新答复，服务端读取已有用例、画像及该用例当前会话的完整历史后生成结果，不覆盖种子数据。

## 阶段路线

| 阶段 | 优先级 | 最小改动 | 验收 |
|---|---|---|---|
| 21 | P0 | 增加服务端会话记录及下一轮生成服务，读取现有用例、画像脚本和已保存历史，生成消息或结束标记 | 同一种子面对不同回答能够作出相应追问，画像和证据边界保持一致，完整历史可恢复 |
| 22 | P0 | 增加一个对外 API，复用现有鉴权、模型配置和图片下载接口 | 外部脚本仅提交用例 ID 和最新答复后可获取下一轮；非法状态、空结果和模型失败有明确反馈 |
| 23 | P1 | 提供一个 Python 调用示例，接入现有跑批脚本，并验证金服测试环境可访问 | 完成一条多轮测试及一个 Web 或 App 接入示例，不要求首版覆盖全部端型 |

### 阶段 21：下一轮生成服务

- 读取已有 `Query`、所选 `QueryVariant` 及其关联画像，复用测试方向、行为逻辑、病例证据和允许发送的图片；不重新运行 Agent F。
- 新增服务端会话记录：一条会话关联 `Query` 和所选 `QueryVariant`，记录状态、当前轮次、开始/结束时间及停止原因；每轮记录服务端生成的用户消息、发送图片和被测系统真实答复。历史只能追加，不能覆盖种子用例或修改先前轮次。
- 首次调用时，服务端为该用例创建当前会话并生成首轮，可复用所选脚本首轮；后续调用只接收最新答复，服务端将其写入当前待回答轮次，再根据完整历史生成下一轮，不机械播放静态脚本。
- 同一用例同一时刻只允许一个进行中的会话，避免仅凭用例 ID 调用时发生历史串线。已结束会话再次调用时创建新会话；进行中的会话必须完成当前轮次后才能继续。
- 复用现有模型调用与可用的上下文构造逻辑；若需要扩展共享编排能力，仅在 `framework.py` 增加必要入口，不复制 runner 或重构现有 Agent 流程。
- 保留必要检查：用例与画像脚本匹配、会话状态、轮次顺序、最大轮数、调用超时、非空消息及合法图片引用。使用数据库事务和行锁保证同一会话不能并发推进。被测系统返回作为不可信数据，不得覆盖生成规则或引入未提供的病例事实；评分背景和内部指令不得出现在 query 中。

### 阶段 22：由服务端维护状态的 API

拟定接口：`POST /external/queries/{query_id}/next-turn`。入口复用现有 `POST /auth/login` 的账号密码登录及 Bearer JWT 校验，不另建外部账号体系。

| 方向 | 字段 | 说明 |
|---|---|---|
| 路径 | `query_id` | 种子用例 ID；服务端据此读取人工选中的画像脚本和当前会话 |
| 输入 | `latest_response` | 被测系统对上一轮的最新答复；首次调用省略或传 `null`，进行中调用必须提供 |
| 输出 | `messages[]`、`images[]` | 本轮应发送的消息及图片引用，图片通过现有鉴权接口获取 |
| 输出 | `conversation_id`、`round` | 服务端会话审计标识和本次生成的轮次，只用于调用方记录与排障，不要求后续回传 |
| 输出 | `done`、`stop_reason` | 是否结束及原因；未结束时必须有有效消息，模型失败不得伪装成正常结束 |

复用现有 JWT／角色鉴权及 OpenAPI 文档，不另建一套外部账号或权限系统。首版采用有超时限制的请求／响应方式，不增加专用异步任务和轮询接口；实际延迟不满足接入要求时，再复用现有 arq 扩展。

服务端按“当前会话必须等待上一轮答复”的状态机推进。调用端每轮只发起一次请求，成功后将结果发送给被测产品；模型调用失败时不推进轮次，保留已写入的最新答复以便受控重试。由于请求只有用例 ID 和答复、没有独立幂等键，网络超时后的自动重发仍可能无法可靠区分重复答复和下一轮内容相同的合法答复，因此首版不自动重发；需要严格幂等时再增加请求 ID，而不是让调用端回传完整历史。

### 阶段 23：最小调用示例与联调

提供一个 Python 示例，展示“用例 ID 获取首轮 query → 发送给被测产品 → 收集真实返回 → 提交用例 ID 和最新答复”的循环及结束处理，供现有跑批脚本复用，不建设通用 SDK、命令行平台或新页面。

金服使用同一 API。先确认测试环境能通过已有部署的内网地址或受控 HTTPS 入口访问服务，再选择一个 Web 或 App 完成联调；页面操作由现有测试工具或人工完成，本项目不负责建设自动化适配框架。

## 最小验证与已知限制

- 增加与本次能力相关的服务／接口测试：会话创建与恢复、上下文引用、不同回答分支、并发推进、轮数上限、空输出、非法画像或图片、未授权访问和模型超时；原有回归测试继续通过。
- 用模拟模型验证接口和规则，再用一条合成或去标识化种子完成真实模型多轮验证，分别记录结果，不能互相替代。
- 历史和测试记录由服务端保存。生成时记录所用种子用例、画像脚本和模型配置的引用；首版不建设回放页面，但数据应支持按会话恢复和审计。

## 暂不纳入本轮

完整种子快照、请求 ID 级持久化幂等、专用队列流程、并发跑批与断点续跑、费用管理、Web／App 适配框架、调试页面、回放看板和自动评分，均等实际使用暴露需要后再单独排期。

此前发现的 Agent F 空脚本成功、ZIP 缺图静默跳过问题作为独立缺陷保留，不再作为动态 API 的整阶段前置改造；新接口只对本次选中的种子脚本和图片做必要校验，遇到缺失明确报错。
