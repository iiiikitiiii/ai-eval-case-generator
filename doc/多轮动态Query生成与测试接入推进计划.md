# 多轮动态 Query 生成与测试接入推进计划

状态：最小实现草案，阶段 21–23 均待开发。本文描述计划，不代表接口已经实现。

## 目标与取舍

只补充一项能力：根据现有画像、种子用例和被测系统真实回答，动态生成下一轮用户 query，供跑批脚本及金服 Web／App 测试调用。

阶段 6 的预生成多轮脚本继续保留。首版不改原有 Agent F 生成、审核及导出流程，不新增服务端会话表，也不建设新的测试平台。调用端保存历史，每轮提交；服务端读取已有用例和画像后生成结果，不覆盖种子数据。

## 阶段路线

| 阶段 | 优先级 | 最小改动 | 验收 |
|---|---|---|---|
| 21 | P0 | 增加下一轮生成服务，读取现有用例及画像脚本，结合对话历史生成消息或结束标记 | 同一种子面对不同回答能够作出相应追问，画像和证据边界保持一致 |
| 22 | P0 | 增加一个对外 API，复用现有鉴权、模型配置和图片下载接口 | 外部脚本提交历史后可获取下一轮；非法输入、空结果和模型失败有明确反馈 |
| 23 | P1 | 提供一个 Python 调用示例，接入现有跑批脚本，并验证金服测试环境可访问 | 完成一条多轮测试及一个 Web 或 App 接入示例，不要求首版覆盖全部端型 |

### 阶段 21：下一轮生成服务

- 读取已有 `Query`、所选 `QueryVariant` 及其关联画像，复用测试方向、行为逻辑、病例证据和允许发送的图片；不重新运行 Agent F。
- 输入包含完整的实际对话历史，上轮真实返回放在历史末尾。首轮历史为空，可复用所选脚本首轮；后续根据真实回答生成，不机械播放静态脚本。
- 复用现有模型调用与可用的上下文构造逻辑；若需要扩展共享编排能力，仅在 `framework.py` 增加必要入口，不复制 runner 或重构现有 Agent 流程。
- 保留必要检查：用例与画像脚本匹配、历史格式和长度、最大轮数、调用超时、非空消息及合法图片引用。被测系统返回作为不可信数据，不得覆盖生成规则或引入未提供的病例事实；评分背景和内部指令不得出现在 query 中。

### 阶段 22：一个无会话状态的 API

拟定接口：`POST /queries/{query_id}/next-turn`。

| 方向 | 字段 | 说明 |
|---|---|---|
| 输入 | `variant_id` | 选择该种子用例下已有的画像脚本，由服务端读取画像与行为逻辑 |
| 输入 | `history[]` | 按顺序提供实际发送的消息、图片引用和被测系统返回；首轮为空，后续须以被测系统返回结束 |
| 输出 | `messages[]`、`images[]` | 本轮应发送的消息及图片引用，图片通过现有鉴权接口获取 |
| 输出 | `done`、`stop_reason` | 是否结束及原因；未结束时必须有有效消息，模型失败不得伪装成正常结束 |

复用现有 JWT／角色鉴权及 OpenAPI 文档，不另建一套外部账号或权限系统。首版采用有超时限制的请求／响应方式，不增加专用异步任务和轮询接口；实际延迟不满足接入要求时，再复用现有 arq 扩展。

调用端每轮只发起一次生成请求，成功后保存结果再发送给被测产品；重复调用可能产生不同结果或额外模型费用，首版不承诺服务端幂等。超时不自动重发，被测产品发送结果不明时先核对。停止测试即停止请求，无需额外 stop 接口。

### 阶段 23：最小调用示例与联调

提供一个 Python 示例，展示“提交历史获取 query → 发送给被测产品 → 收集真实返回 → 更新历史”的循环及结束处理，供现有跑批脚本复用，不建设通用 SDK、命令行平台或新页面。

金服使用同一 API。先确认测试环境能通过已有部署的内网地址或受控 HTTPS 入口访问服务，再选择一个 Web 或 App 完成联调；页面操作由现有测试工具或人工完成，本项目不负责建设自动化适配框架。

## 最小验证与已知限制

- 增加与本次能力相关的服务／接口测试：上下文引用、不同回答分支、轮数上限、空输出、非法画像或图片、未授权访问和模型超时；原有回归测试继续通过。
- 用模拟模型验证接口和规则，再用一条合成或去标识化种子完成真实模型多轮验证，分别记录结果，不能互相替代。
- 历史和测试记录由调用端保存；服务端首版不提供会话查询、恢复或回放。每次读取当前种子和配置，测试期间应避免修改，暂不保证跨版本复现。

## 暂不纳入本轮

服务端会话／快照系统、持久化幂等、专用队列流程、并发跑批与断点续跑、费用管理、Web／App 适配框架、调试页面、回放看板和自动评分，均等实际使用暴露需要后再单独排期。

此前发现的 Agent F 空脚本成功、ZIP 缺图静默跳过问题作为独立缺陷保留，不再作为动态 API 的整阶段前置改造；新接口只对本次选中的种子脚本和图片做必要校验，遇到缺失明确报错。
